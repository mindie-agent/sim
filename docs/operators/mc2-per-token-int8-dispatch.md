# Source-selected MC2 INT8 per-token dispatch

Development-run reports cited below are historical context and are not shipped. Current acceptance is documented in [verification](../verification.md).

`runtime.kernels.native_moe_protocol` now accepts:

```json
{"kind":"arch35_fullmesh","max_inflight_per_rank":8,"dispatch_quant":"per_token_int8"}
```

This explicitly selects the existing fullmesh `per_token` INT8 row representation. It does not change the unselected/`none` or MX branches. FP16/BF16 source rows are cast and dynamically quantized once at the dispatch sender; one FP32 scale per row travels with the INT8 payload. The ordinary grouped gate consumes the received payload and scales after dispatch completes. Its generic input quantizer is removed only when its dtype, K-wide group, row-scale shape, scale bytes and direct dependency match that producer. The independent expert down quantizer and declared FP16/BF16 expert return remain.

Pinned `ops-transformer` source revision `a3925fd49cd256ad478d2faf983bf2961b8ae2c8`, `mc2/moe_distribute_dispatch_v2/op_kernel/moe_distribute_dispatch_v2_quant.h` SHA-256 `46fec97abaec206c9b41bd1b3ab690d7c0ff7fe7a09961599b8c56f304543ed5`, lines 171–224, supplies the dynamic per-token branch: FP32 cast, abs/max reduction, rescaling, three INT8 conversion casts, FP32 reciprocal scale publication. The existing source ledger charges `7*width-1` vector element operations per assignment and retains scalar reciprocal/scale-store instruction latency as unmodeled. This change connects that ledger to the ordinary graph; it adds no timing constants or new kernel model.

For width 2048, each dispatch row carries 2048 payload bytes, 4 scale bytes and its source triple; source framing emits five 512-byte packets. Receiver materialization is 2064 bytes including the 12-byte triple. BF16 combine returns nine packets per row. Whole rows are framed before assignment counts are applied. Integer routing provides exact received scale rows; statistical routing keeps the existing expected-work closure (allocated scale shape uses ceil(received rows), while priced scale bytes retain expected rows). Neither representation infers group_list values from output capacity.

The 12 dedicated controls run real ordinary frontend and Engine paths: one producer, retained down quantization, exact integer scales and transpose wire accounting with idle/unequal DP, a 17 ms late route, incompatible block-scale rejection, one outer invocation, and five resource axes at 0.5/1/2. Together with existing MX/fullmesh/ownership tests: **58 passed in 0.83 s**. Hardware rates and semantic work remain unchanged. These are mechanism controls, not capture accuracy claims; native quantization flags, scalar timing, polling iterations and dispatch implementation identity still require independent evidence.

The native dispatch exit now also publishes the typed **receiver** contract itself: `returns=(activation_scales,)`, payload shape, scale shape/dtype/bytes and expected received rows. The exit follows local materialization and flag retirement. Sender `local_shape` is deliberately not reused for this output: an idle source can receive expert rows. This permits the existing strict `ascend_grouped_int32_dequant_swiglu` caller to read dispatch-produced FP32 scales without weakening its producer checks or inventing a second gate quantizer. The down quantizer survives inside the selected `DequantSwigluQuant` invocation. All 40 layers at actual Qwen c4/c64/c128 geometry and a late-input one-layer execution exercise this combined path; a separate idle-source case verifies receiver rows differing from the source shape. Joint controls: **39 passed in 1.40 s**.

`tools/verify_source_callers.py` now adds two installed public CLI checks using the real Qwen3.5 c4 case reduced to one complete layer, retaining its source GDN, W8A8, grouped INT32 and source AIV AllGather declarations. The combined path was built into a wheel and installed offline in a fresh environment; `python -I` from outside the checkout passed `graph --scope body` (0.367 s) and `predict --scope body` (0.237 s), with no live tasks/programs/allocations. The graph control verifies full router M16, local source M4, received expert rows32, 128 FP32 scale bytes, retained DequantSwigluQuant, and 16 KiB local AllGather input. Timing is a synthetic mechanism result, not model accuracy. Installed receipt records the wheel digest, source hashes and resolved installed import path. The verifier is already invoked by `tools/verify_wheel.py`; no additional verifier entry point was introduced.
